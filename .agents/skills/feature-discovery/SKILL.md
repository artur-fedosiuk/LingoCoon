# Feature Discovery

## Inputs

Require a learner problem, affected segment, desired outcome, and known constraints. Read the relevant product documents and inspect current source before assuming capability.

## Procedure

1. Separate verified problem evidence from assumptions and solution ideas.
2. Map the current flow, data touched, learning rationale, and failure states.
3. Compare the smallest useful option with realistic alternatives.
4. Define personalization, accessibility, privacy, security, cost, and dependency effects.
5. Specify success, guardrail, and learning metrics plus stop/continue criteria.
6. Identify the exact product, architecture, or external decision requiring approval.

## Output and validation

Return a concise brief: problem, segment, evidence, hypothesis, MVP, alternatives, metrics, risks, dependencies, acceptance criteria, and open decision. Link source files and dated external evidence. Do not modify code, data, configuration, or external systems without separate approval.
